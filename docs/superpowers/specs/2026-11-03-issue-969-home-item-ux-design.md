# #969 홈 피드·물품 등록·상세 사용성 개선 설계

- 이슈: https://github.com/TEAM-ROMROM/RomRom-FE/issues/969
- 원칙: 사용자가 누른 동작은 항상 반응(로딩·성공·실패), 실패와 "없음" 구분(`EmptyStateView`/`.error`), 잘못된 값 저장 경로는 실패 시 이전 값으로 복원
- 범위 밖: 서버 변경 항목(광고 전 자격 확인, 원하는 교환 물건, 검색, 거리), "내 물품 없으면 피드 블러"(현행 유지)
- 다른 이슈 소유 파일은 건드리지 않음: 딥링크·삭제 물품 화면·알림·스플래시·마이페이지 탭·프로필(#972), 요청 화면·요청 관리(#970), 채팅·교환 상대 선택·후기(#971)

## 홈 피드, 카드 덱

| 항목 | 문제 | 변경 | 테스트 |
|---|---|---|---|
| 수동 새로고침 | 빈 피드 '새로고침'이 30초 제한에 걸리면 무반응 | `RefreshTrigger`에 `manualRefresh`·`searchRangeChanged` 추가, `shouldBypassThrottle`로 제한 우회. `refresh`가 `HomeFeedRefreshResult`(refreshed·skipped·failed) 반환 > 빈 피드 버튼 로딩 표시, 실패·여전히 비어 있음 안내 | provider: 수동 트리거 제한 우회, 실패 결과, 자동 트리거 제한 결과 |
| 광고 실패 칸 | 광고 로드 실패 시 스켈레톤이 남고 카드 드래그·상단 버튼이 막힘 | `NativeAdWidget.onLoadFailed`(광고 ID 없음 포함) > `HomeFeedAdSlotSchedule.removeAdAtVirtualIndex`로 칸 접기 > 현재 페이지 보정 | 슬롯 스케줄 단위 테스트 |
| 신고 물품 | 신고해도 피드에 남음 | `HomeFeedNotifier.excludeReportedItem` > 현재 목록·이후 페이지에서 제외 (서버가 신고 물품을 빼 준다는 보장이 없어 세션 동안 클라이언트에서 거름) | provider: 현재 목록 제외, loadMore·refresh 결과에서도 제외 |
| 블러 문구 | 물품이 모두 교환 완료된 사용자에게 "먼저 나의 물품을 등록해 주세요!" | 교환 완료 물품이 있으면 "교환 가능한 물품이 없어요" 문구 | 문구 선택 함수 테스트 |
| AI 추천 안내 | 실패·결과 0개일 때 무반응 | 실패 > 오류 토스트, 0개 > 안내 토스트 + 버튼 해제 | 수동 확인 |
| 빈 피드 안내 | 다음 행동 안내 없음 | `EmptyStateView`에 보조 버튼 추가 > "탐색 범위 넓히기"(탐색 범위 화면) | 공통 위젯 테스트 |
| 카드 덱 실패 | 내 물건 조회 실패 시 카드 덱이 설명 없이 비어 있음 | 실패(값 없음)면 하단에 "내 물품을 불러오지 못했어요 · 다시 시도" 버튼 | 위젯 테스트 |

## 물품 상세

| 항목 | 문제 | 변경 | 테스트 |
|---|---|---|---|
| 교환 완료 흐름 | 메뉴 '교환완료로 변경'이 확인·상대 선택 없이 상태 변경 | 등록 탭과 같은 흐름: `TradeCompletePartnerSelectScreen` > 채팅방(`autoTriggerExchangeRequest`). '교환 가능으로 변경'은 확인 창 후 변경 | 수동 확인 |
| 요청하기 버튼 | 교환 완료 물품에도 노출 | 교환 가능 상태일 때만 노출 | 수동 확인 |
| 삭제 물품 | 일반 오류 + 소용없는 '다시 시도' | `ErrorUtils.getErrorCode` 추가 > `DELETED_ITEM`·`ITEM_NOT_FOUND`면 화면 안 "삭제된 물품" `EmptyStateView`(재시도 없음) | `getErrorCode` 단위 테스트 |
| 삭제 문구 | 상세·등록 탭 문구 다름 | `context.showItemDeleteConfirmDialog()` 단일 원본 | 수동 확인 |

| 항목 | 문제 | 변경 | 테스트 |

| 수정 화면 실패 | 물품 못 불러오면 빈 폼 + '수정 완료' | `EmptyStateView.error` + 다시 시도 | 위젯 테스트 |
| 위치 폴백 | 권한 거부·실패 시 안내 없이 서울시청 (FIXME) | `LocationService.fallbackPosition` 상수 + "기본 위치로 표시했어요" 안내 | 수동 확인 |
| 현재 위치 버튼 | 실패해도 무반응 | 실패 안내 토스트, 진행 중 중복 탭 무시 | 수동 확인 |
| 사진 재업로드 | 등록 실패 후 재시도 시 이미 올린 사진 재업로드 | `NewImageUploadCache`: 원본 파일별 업로드 주소 기억 > 안 올린 것만 업로드 | 단위 테스트 |
| 주소 실패 | 수정 모드 주소 변환 실패 시 위치 칸 비어 완료 버튼 막힘 | 좌표가 있으면 "기존 위치 (주소 확인 불가)" 표시 > 기존 좌표로 저장 가능 | 수동 확인 |
| AI 표시 해제 | 제목·설명·상태를 바꿔도 AI 가격 표시가 남음 | `AiPriceBasis`(AI 측정 당시 제목·설명·상태) 기준과 달라지면 AI 표시 해제 | 단위 테스트 |

## 등록 탭, 내 물건, 우선 노출

| 항목 | 문제 | 변경 | 테스트 |
|---|---|---|---|
| 탭별 빈 문구 | 교환 완료 탭도 "등록된 물품이 없어요." | `MyItemToggleStatus`에 빈 상태 문구·설명 > 두 화면이 `EmptyStateView`로 표시 | enum·화면 테스트 |
| 교환 가능 확인 문구 | 제목과 설명이 같은 문장 | 건너뜀: `showDeleteDialog`는 `title`을 화면에 그리지 않아 사용자에게 같은 문장이 두 번 보이지 않음. 해당 블록은 #971 수정 범위 | - |

## 좋아요, 탐색 범위, 카테고리

| 항목 | 문제 | 변경 | 테스트 |
|---|---|---|---|
| 홈 이동 | '홈에서 둘러보기'가 마이페이지 탭으로 돌아감 | 탭 0 지정 > 첫 화면까지 pop | 수동 확인 |
| 가격 | 좋아요 목록에 가격 없음 | 가격 표시 | 수동 확인 |
| 되돌리기 | 하트 해제 즉시 목록에서 사라져 되돌릴 수 없음 | 해제한 물품은 빈 하트로 남김 (다시 누르면 복구), 새로고침 시 정리 | 수동 확인 |
| 다음 페이지 실패 | 실패 표시 없음 | 하단 "다시 시도" + 토스트, 실패 중 자동 재요청 멈춤 | 수동 확인 |
| 탐색 범위 오류 | 네트워크 오류도 "내 위치를 먼저 설정해주세요" | 조회 실패는 `EmptyStateView.error` + 다시 시도 | 위젯 테스트 |
| 탐색 범위 저장 실패 | 화면 값이 그대로 남음 | 마지막 저장 성공 값으로 복원 (마지막 요청 결과만 반영) | 수동 확인 |
| 피드 갱신 | 저장해도 홈 피드 그대로 | 저장 성공 시 `refresh(searchRangeChanged)` (제한 우회) | provider 테스트(트리거) |
| 10km 초과 | 2.5km로 표시 | `searchRangeIndexForRadius`: 가장 큰 범위로 표시 | 단위 테스트 |
| 카테고리 로딩 | 응답이 비면 계속 로딩 | 응답과 관계없이 로딩 종료 | 위젯 테스트 |
| 카테고리 저장 차단 | 불러오기 실패 시 빈 선택으로 저장 가능 | 실패면 에러 뷰 + 다시 시도, 저장 버튼 숨김 | 위젯 테스트 |
