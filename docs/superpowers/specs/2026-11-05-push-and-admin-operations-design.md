# 푸시 고도화 · 관리자 운영 기능 설계

- 요청: "알림 쪽 관리자 화면 개선, 푸시 고도화, 실제 운영 앱처럼 관리자에서 제대로 관리" (2026-11-05, 설계·구현 전부 위임)
- 선행: BE #873(키워드 알림, 채팅 신고 탭, 공지 이미지·링크), FE #1020(키워드 알림 앱)
- 기준: origin/main b130fe0d 조사 결과

## 1. 왜

현재 운영자가 할 수 있는 푸시는 "공지 만들 때 전체 발송"과 "회원 1명에게 보내기" 두 가지뿐이다.

- 공지 푸시는 수신 동의를 확인하지 않는다
- 발송 기록·성공/실패 수가 남지 않고, 예약 발송·대상 선택·테스트 발송이 없다
- 광고성 푸시 법규 처리가 없다: "(광고)" 표시, 야간(21~08시) 발송 제한, 수신 동의 확인, 2년마다 동의 상태 안내
- 토큰 처리 버그로 푸시가 조용히 끊긴다
  - 토큰이 갱신돼도 저장되지 않음
  - 기기 종류당 토큰이 1개뿐임
  - 로그아웃해도 토큰이 남음
- 관리자 행동 기록은 제재·채팅 조치만 남는다. 설정 변경·공지·팝업·물품 수정·신고 처리는 로그 파일에만 있다

## 2. 목표

1. **푸시가 확실히 간다**
   - 토큰 갱신·다중 기기·로그아웃 정리
   - 일괄 발송(sendEach 500건 단위)
   - 무효 토큰 정리
   - 플랫폼별 페이로드 정리
2. **운영자가 푸시를 직접 운영한다**
   - 관리자 "푸시 발송" 화면: 작성 > 대상 > 미리보기(대상 수) > 테스트 발송 > 즉시·예약 발송
   - 발송 기록: 대상 수·성공·실패·열람 수
3. **법규를 지킨다**: 정보성·광고성을 구분하고, 광고성은 자동으로 처리한다
4. **누가 무엇을 바꿨는지 남긴다**: 관리자 작업 기록과 기록 조회 화면
5. **목록을 내보낼 수 있다**: 회원·물품·신고 CSV

## 3. 하지 않는 것 (이번 범위 밖)

- 1:1 문의 게시판: 현재 이메일 문의로 운영. 문의가 늘면 별도 진행
- 관리자 계정 여러 개·권한 등급·2단계 인증: 운영자 1인 체제라 지금은 불필요
- 피드 추천 점수 변경, A/B 테스트, 위치 기반 지오펜스 발송
- settings.html(1518줄) 분리. 이번에 손대지 않음 (플랫폼별 최신 버전은 CI가 이미 동기화)

## 4. 설계

### 4.1 토큰·발송 파이프라인 (서버)

**토큰 저장**
- 기준 키를 (회원, 기기 종류)에서 **토큰 값**으로 바꾼다 (unique)
- 같은 토큰이 다른 회원으로 들어오면 그 회원에게 옮긴다 (기기를 같이 쓰다 계정을 바꾼 경우)
- 회원 1명이 여러 기기를 쓸 수 있다
- 갱신된 토큰은 반드시 저장한다 (현재 버그 수정)
- 마이그레이션: 중복 토큰 행 정리 > unique 제약

**로그아웃 시 토큰 삭제**
- 로그아웃 요청에 선택 파라미터 `fcmToken`을 받는다 (추가만 하므로 옛 앱에는 영향 없음)
- 해당 토큰 행만 삭제한다

**오래된 토큰 정리**
- 앱은 시작할 때와 토큰이 갱신될 때 토큰을 다시 보낸다 (firebase_service.dart)
- 매일 스케줄러가 갱신일이 90일 지난 토큰을 삭제한다

**일괄 발송**
- `FirebaseMessaging.sendEach`를 500건 단위로 묶어 보낸다
- 응답의 오류 코드가 `UNREGISTERED`·`INVALID_ARGUMENT`(토큰 형식)·`SENDER_ID_MISMATCH`이면 그 토큰을 삭제한다
- 성공 수·실패 수·삭제한 토큰 수를 돌려준다

**페이로드**
- Android: channel id `high_importance_channel` (앱 manifest와 일치), priority high, TTL 1일(광고 6시간)
- iOS: sound default, `apns-priority` 10, badge = 안 읽은 알림 수 (1명에게 보낼 때만, 일괄 발송은 생략)
- 깨진 상대경로 로고 이미지는 제거하고, 캠페인 이미지 URL이 있을 때만 넣는다
- data에 `campaignId`를 넣는다 (캠페인 발송일 때만)

**공지 푸시**
- 정보성 발송으로 처리한다
- 콘텐츠 알림 동의(`isContentNotificationAgreed`)한 회원에게만 보낸다
- 알림 기록(notification_history)을 모든 활성 회원에게 남긴다. 동의하지 않았거나 방해금지 시간이라 푸시를 못 받은 회원도 앱 알림 목록에서는 볼 수 있다

### 4.2 푸시 캠페인 (서버 + 관리자 화면)

**테이블 `push_campaign`**

| 항목 | 내용 |
|---|---|
| 기본 | id, title, body, imageUrl, deepLink |
| 구분 | purpose: INFORMATION / ADVERTISEMENT |
| 대상 | targetType: ALL / SEGMENT / MEMBERS / TEST, targetFilter(JSON) |
| 상태 | status: SCHEDULED / SENDING / COMPLETED / FAILED / CANCELED |
| 시각 | scheduledAt, startedAt, completedAt |
| 집계 | targetMemberCount, sentCount, failureCount, removedTokenCount, openedCount |
| 기타 | createdByAdminId, failureReason |

**대상**
- ALL: 전체 활성 회원
- SEGMENT 필터
  - 기기 종류: Android / iOS
  - 마케팅 동의 여부
  - 최근 활동: N일 이내 / N일 이상 미접속
  - 가입일 범위
  - 지역: 시·도 (회원 locationAddress 앞부분)
- MEMBERS: 회원 ID·이메일·닉네임 목록 붙여넣기
- TEST: 관리자 본인 계정의 토큰. 기록에는 남기지만 통계에서는 뺀다

**발송 규칙**

| | 정보성 | 광고성 |
|---|---|---|
| 수신 동의 | 콘텐츠 알림 동의자 | 마케팅 수신 동의자만 |
| 제목·본문 | 그대로 | 제목 앞에 "(광고) " 자동, 본문 끝에 "수신거부: 설정 > 알림 설정" 자동 |
| 발송 시간 | 제한 없음 | 21:00~08:00(KST) 예약 거부. 실행 시점에 야간이면 발송하지 않고 FAILED + 사유 |
| 알림 종류 | `ANNOUNCEMENT` | 새 종류 `MARKETING` (옛 앱 목록에서 숨김) |

- 회원 개인의 방해금지 시간은 두 경우 모두 지킨다. 그 시간이라 못 받은 회원에게는 알림 기록만 남긴다
- 알림 기록은 대상 회원 전원에게 남긴다. 앱 알림 목록에서 누르면 deepLink로 이동한다

**실행**
- 즉시 발송: 생성 후 비동기로 실행
- 예약 발송: 1분 주기 스케줄러가 시각이 된 SCHEDULED 캠페인을 실행한다
- 상태를 조건부로 업데이트(SCHEDULED > SENDING)해서 두 번 발송되지 않게 한다
- 예약 캠페인은 시작 전에만 취소할 수 있다

**미리보기**
- 대상 회원 수와 토큰 수를 실제로 보내지 않고 계산한다 (dry run)

**열람 추적**
- 앱이 `campaignId`가 들어 있는 푸시를 열면 `POST /api/notification/push-open` (form `campaignId`)을 호출한다
- 같은 회원이 같은 캠페인을 여러 번 열어도 1회로 센다 (push_campaign_open 테이블, unique)

**관리자 화면 `/admin/push`**
- 작성 폼 (정보성·광고성 선택 시 표시 문구 미리보기, 휴대폰 알림 모양 미리보기)
- 대상 선택과 대상 수 미리보기
- 테스트 발송 버튼, 즉시·예약 발송
- 캠페인 목록: 상태·대상·성공·실패·열람 수·열람률, 예약 취소, 상세

**회원 상세의 "알림 보내기"**
- MEMBERS 대상 캠페인 1건으로 처리해 같은 기록·통계에 쌓는다
- 목적과 딥링크를 고를 수 있게 한다

**딥링크 입력**
- 없음 / 공지 상세 / 물품 상세(ID) / 직접 입력(romrom://, https://)
- 서버에서 형식을 검증한다

### 4.3 마케팅 수신 동의 기록 · 2년 안내 (서버)

- `member.marketing_consent_changed_at` 컬럼을 추가하고, 동의를 바꿀 때마다 기록한다
  - 기존 동의자는 마이그레이션 시점 값을 updated_date로 채운다
- 매일 스케줄러가 동의 시각 + 2년이 지난 동의자에게 정보성 안내를 보내고, 안내 시각을 기록한다
  - 안내 문구: "마케팅 정보 수신 동의 상태 안내 (동의일 yyyy.MM.dd)"
  - 다음 안내는 그로부터 2년 뒤

### 4.4 관리자 작업 기록 (서버 + 화면)

- 테이블 `admin_audit_log`
  - 관리자 ID·이메일, action(enum), 대상 종류·ID, 요약, 요청 파라미터 요약(비밀값 제외), IP, 시각
- 기록 방식: 관리자 API 중 변경 엔드포인트에 `@AdminAudit(action=...)` 어노테이션 + AOP
  - 성공한 요청만 남긴다 (실패는 로그 파일)
  - 대상: 설정 변경, 공지, 팝업, 물품 수정·삭제·숨김, 거래 강제 처리, 후기 블라인드, 신고 처리, 채팅 조치, 회원 제재·수정·토큰 삭제, 푸시 캠페인
  - 기존 SanctionHistory는 그대로 둔다
- 화면 `/admin/audit-logs`: 기간·관리자·action·대상 필터, 페이지

### 4.5 CSV 내보내기 (서버 + 화면)

- 회원·물품·신고 목록 화면에 "CSV 내보내기" 버튼
- 현재 필터를 그대로 적용하고, 최대 10,000행
- UTF-8 BOM을 붙인다 (엑셀 한글 깨짐 방지)
- 개인정보 최소화: 이메일은 마스킹, 전화번호는 없음
- 내보내기도 작업 기록에 남긴다

### 4.6 앱 (RomRom-FE)

- 로그아웃할 때 현재 FCM 토큰을 서버에 보낸다 (선택 파라미터)
- `campaignId`가 있는 푸시를 열면 push-open을 보낸다
  - 실패해도 무시한다
  - 앱 시작 경로·백그라운드 경로·포그라운드 탭 모두에서 보낸다
- 새 알림 종류 `marketing`(label "이벤트·혜택", serverName `MARKETING`)
  - 끄기 메뉴는 마케팅 수신 설정에 연결한다
  - 누르면 deepLink로 이동한다

## 5. 호환성

- 옛 앱(v1.10.142 이상)이 그대로 동작해야 한다. API는 추가만 한다
- 새 알림 종류는 옛 앱 목록에서 숨긴다(LEGACY_CLIENT_HIDDEN_TYPES)
- 옛 앱도 푸시 자체는 시스템 알림으로 받는다
- 토큰 unique 마이그레이션은 중복 행을 먼저 정리한 뒤 진행하고, 몇 행을 정리했는지 NOTICE로 남긴다

## 6. 작업 순서 (구현 단위)

1. 토큰·발송 파이프라인 (4.1) + 테스트
2. 푸시 캠페인 백엔드 + 스케줄러 + 열람 추적 API (4.2) + 테스트
3. 관리자 푸시 화면 + 회원 상세 알림 보내기 연결 (4.2)
4. 동의 기록 · 2년 안내 (4.3)
5. 관리자 작업 기록 + 화면 (4.4)
6. CSV 내보내기 (4.5)
7. 앱 변경 (4.6)

## 7. 판단 (사용자 위임으로 내가 정한 것)

- 공지 푸시는 콘텐츠 동의자에게만 보내고, 기록은 전원에게 남긴다
- 광고성은 마케팅 동의자에게만 보내고, 야간 발송은 거부한다 ("(광고)" 표시, 수신거부 안내 자동)
- 오래된 토큰은 90일 뒤 정리, 일괄 발송은 500건 단위
- 1:1 문의, 관리자 권한 등급, settings.html 분리는 이번에 하지 않는다
